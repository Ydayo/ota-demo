# ADR-0016: 役割(OTA_ROLE)を廃止し、人間の確認と PR の分離で保護対象を守る

- 日付: 2026-09-27
- 関連: ADR-0006 の「役割によるロック解除」を置き換える。ADR-0015 の「役割 harness だけが変更できる」を置き換える

## 背景

ADR-0006 では、人間がセッション起動時に環境変数 `OTA_ROLE` で役割を指定し、役割に応じて保護対象への書き込みを許可した。運用すると次の問題があった。

- 役割を切り替えるたびに、人間がセッションを起動し直す必要があり、手間が大きい。
- AI は Bash から役割つきの子セッションを起動するなどして迂回でき、保護としての効果が限られる。

## 決定

### ローカル(早期フィードバック)

- 役割(`OTA_ROLE`)を廃止する。
- PreToolUse hook は、保護対象への書き込みに対して Claude Code の確認ダイアログを出す(`permissionDecision: "ask"`)。人間が内容を見て、毎回許可または拒否する。
  - 対象: 仕様・用語集・ADR、受け入れテスト、ハーネス(保護対象の一覧は ADR-0006、ADR-0015 のとおり)
- 憲法(`docs/constitution.md`)と `~/.claude/` への書き込み、ゲートの迂回(`--no-verify`、強制 push、Bash からの `claude` の起動、`gh auth`)は常に拒否する。
- 確認ダイアログを出せない環境(Bash から起動した `claude -p`、確認を出さない権限モードなど)では、確認が必要な操作は実行されない。

### CI(最終防衛線)

- **実装を変更する PR は、仕様・用語集・ADR と受け入れテストを変更してはならない。** CI で検査し、違反すれば失敗させる。
  - これにより、実装の PR で受け入れテストを弱めることが構造的にできなくなる。仕様や受け入れテストの変更は別の PR となり、CODEOWNERS により人間のレビューを必ず通る。
  - ハーネスの変更は実装と同じ PR に含めてよいが、CODEOWNERS により人間のレビューを必ず通る。
- 「実装」は、保護対象(ADR-0006、ADR-0015)以外のすべてのファイルとする。

### サブエージェント

- spec-author、test-author、implementer、reviewer のサブエージェントは残す。役割は作業の文脈を分けるためのものであり、書き込みの許可には関係しない。

## 検討した選択肢

- CI の PR 分離だけにする(ローカルでは止めない): 最も単純だが、誤った書き込みに気づくのが PR の段階まで遅れるため不採用。
- 保護対象への書き込みを常に拒否する: 仕様の作成や Grilling での用語集の更新も AI ができなくなり、仕様駆動の進め方と合わないため不採用。

## 結果

- 役割の切り替えのためにセッションを起動し直す必要がなくなる。
- 保護対象への書き込みは、必ず人間がその場で確認する。
- 実装の PR で仕様や受け入れテストを変えることは、CI によってできない。
- 仕様の作成中は、確認ダイアログが何度も表示される。

## 出典(確認日: 2026-09-27)

- PreToolUse hook の `permissionDecision: "ask"` は通常の確認ダイアログを表示する: https://code.claude.com/docs/en/hooks-guide.md
- auto モードでも、hook による確認ダイアログは表示される: https://code.claude.com/docs/en/permission-modes.md
- 確認を出せない非対話の実行では、確認が必要な操作は実行されない: https://code.claude.com/docs/en/headless.md 、 https://code.claude.com/docs/en/permission-modes.md
- 確認を出さない権限モード(dontAsk、bypassPermissions)での hook の `ask` の扱い: ドキュメントに明記がなく未確認。これらのモードはこのプロジェクトでは使わない。
