# ADR-0009: 業務上のエラーは Result 型で表す

- ステータス: 提案中
- 日付: 2026-09-27

## 背景

業務上のエラー(在庫切れ、不正な宿泊期間など)を例外で表すと、関数のシグネチャからエラーの可能性が読み取れず、処理漏れを型検査で検出できない。

## 決定

- 業務上のエラーは `Result<T, E>` で返す。`E` は判別共用体で、エラーの種類を型で列挙する。
- `Result` は `@ota/shared` に最小限の自前実装を置く。domain の外部依存ゼロを保つため、外部ライブラリ(neverthrow など)は使わない。
- 例外は、プログラムの誤り(不変条件の違反)と、回復不能な技術的障害にのみ使う。
- プレゼンテーション層で、エラーの種類を HTTP ステータスとレスポンスに変換する。

## 検討した選択肢

- 例外: エラーの可能性が型に現れないため不採用。
- neverthrow などのライブラリ: domain に外部依存が入るため不採用。

## 結果

- エラーの処理漏れがコンパイル時に検出される。
- エラーの種類ごとの分岐がテストしやすくなり、ミューテーションテストの検出力も上がる。
