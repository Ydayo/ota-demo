# ADR-0013: 人間が承認した PR は、承認されたコミットを指定して bot がマージする

- 日付: 2026-09-27
- 関連: ADR-0007 の「人間は PR のレビュー、承認、マージをブラウザで行う」のうち、マージの担い手を変更する

## 背景

ADR-0007 では、人間が PR のレビュー・承認・マージをブラウザで行うと決めた。運用してみると、承認とマージを別々に操作する手間がある。人間は承認までを行い、マージは AI に任せたい。

## 決定

- 人間が承認した PR は、bot(`ydayo-bot`)がマージしてよい。
- マージの API には、人間が承認したコミットの SHA を指定する(`PUT /repos/{owner}/{repo}/pulls/{number}/merge` の `sha`)。承認後に別のコミットが加わっていれば、マージは失敗する。
- マージの前に、PR のレビュー状態が「承認済み」で、承認されたコミットが PR の先頭のコミットと一致することを確認する。
- マージの方法は squash とする。
- ADR-0007 のその他の決定(ルールセット、人間の認証情報を CLI に置かないこと、人間の変更はバイパスでマージすること)は変更しない。

## 検討した選択肢

- 人間がマージまで行う(ADR-0007 のまま): 安全性は同じだが、操作が1つ増えるため不採用。
- 承認されたら自動でマージする(GitHub の auto-merge): 承認の直後に CI が失敗した場合などの確認の機会がなくなるため、現時点では不採用。

## 結果

- 人間の操作は承認のみになる。
- ルールセット(承認必須、新しい push で古い承認を取り消す、最新の push は別の人の承認が必要)と SHA の指定により、承認されていない変更が main に入ることはない。

## 出典(確認日: 2026-09-27)

- PR のマージ API の `sha` パラメータ(先頭のコミットがこの SHA と一致する場合のみマージする): https://docs.github.com/en/rest/pulls/pulls#merge-a-pull-request
